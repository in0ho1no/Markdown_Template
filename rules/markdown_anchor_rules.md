# Markdown記述ルール: 見出しへのIDアンカー付与

文書内で章節を相互参照する際の記述ルールを定める。

## 背景: 解決したい問題

章節の相互参照に使われる一般的な2方式には、それぞれ弱点がある。

| 方式 | 記述例 | 弱点 |
| --- | --- | --- |
| 番号参照 | §9.3 参照 | 節の挿入・削除で番号がずれる。参照が別の実在節を指すため、誤りに気付けない(検知手段がない) |
| 見出し名参照 | 「設定とシークレットの管理」参照 | 文が冗長になる。リネームで追随が必要 |

いずれも「短く書ける」と「変更に強い」を両立できない。
そこで本ルールでは、位置とも題名とも独立した ID を見出しに振り、参照は ID で行う。

| 変更の種類 | 番号参照 | 名前参照 | ID参照 |
| --- | --- | --- | --- |
| 節の挿入・削除 | ずれる(気付けない) | 影響なし | 影響なし |
| 見出しのリネーム | 影響なし | 追随が必要 | 影響なし |
| 記述の短さ | 短い | 長い | 短い |
| 機械的な検知 | 不可 | 不可 | 可能な場合がある |

ID は見出しの位置にも題名にも依存しないため、節を差し込んでも見出しを書き換えても参照は生きたままになる。
参照先が別の節に化けることが原理的に起こらない。

## ルール

### 記法

相互参照の対象となる見出しには、見出し行の末尾に不可視のアンカーを埋め込む。

```markdown
### バックエンド <a id="llm-backend"></a>
```

参照はその ID で行う。

```markdown
詳細は [#llm-backend](#llm-backend) を参照
モデル ID は設定ファイルから取得する（[#config-secrets](#config-secrets)）
```

:::info
`<a id="...">` は多くのレンダラで機能するが、GitHub は id 属性を書き換える仕様があり、`<a name="...">` の方が確実とされる。GitHub での閲覧を主用途とする文書では `<a name="...">` の併記を検討する。
Pandoc / kramdown 系の `### 見出し {#id}` 記法は簡潔だが、GitHub では解釈されず文字列がそのまま表示される。汎用性を優先し、本ルールでは生の `<a>` 要素を使う。
:::

### 命名規約

- ASCII の kebab-case とする。日本語を使わない(レンダラ間でのアンカー算出差異を避けるため)
- 意味ベースで付ける。`sec-3-2` のような位置ベースは番号方式と同じ問題に戻るため禁止
- 接頭辞で名前空間を分けると衝突しにくい(例: `sec-`, `fig-`, `tbl-`)
- 一度公開した ID は変えない。変える場合は grep で全参照を追い、漏れなく置換する

### 適用範囲の判断

すべての文書・見出しに一律適用するものではない。以下を目安に判断する。

- 向くケース: 長期間保守する仕様書・設計書、章節の増減が見込まれる文書、相互参照が多い文書
- 不要なケース: 参照がほとんどない短い文書、使い捨ての文書。ID の維持コストが利点を上回る

適用する文書でも、アンカーを付けるのは参照される見出しだけでよい。

## 導入前に確認すべきこと

### レンダラの互換性

実際に使うレンダラ(GitHub、静的サイトジェネレータ、エディタのプレビュー)すべてで、表示とリンク動作を確認する。

### lint設定との整合

- インライン HTML を禁止するルール(markdownlint の MD033 等)に抵触するため、`a` 要素の許可設定が必要
  - 本リポジトリの `.markdownlint.jsonc` では許可済み
- リンク断片の整合を検証するルール(markdownlint の MD051 等)は、明示アンカーを認識できる。日本語見出しの自動アンカーと算出方式がずれて誤検知するために無効化している環境でも、ID が ASCII なら不一致が起きないため再有効化できる可能性がある。これが有効になれば、参照切れを CI や保存時に自動検知できる — 番号方式では得られない利点
- ただし自動生成 TOC を併用している場合、そちらの誤検知が復活しないかは要確認
  - 本リポジトリは Markdown Preview Enhanced の自動生成 TOC(日本語見出し)を使うため、MD051 は無効のままとする

### 目次の自動生成との共存

見出し行に HTML が入ることで、TOC 生成ツールが見出しテキストをどう拾うか(アンカーが混入しないか)を確認する。

## 移行手順(既存文書に適用する場合)

1. 1 セクションだけに ID を付け、全レンダラで表示・リンクを確認する
1. lint 設定を調整し、警告が出ないことを確認する
1. 問題なければ全体へ展開する。既存の番号参照は ID 参照へ機械的に置換する
1. 参照切れ検知(MD051 等)を有効化できるか試す

:::warning
いきなり全置換すると、表示崩れが起きたときの切り分けが難しくなる。手順 1 と 2 を先に済ませること。
:::
